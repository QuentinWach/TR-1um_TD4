# ピン割当 / I/O 計画 — TD4 on TR-1um

**2026-09-12 §5/§7 改訂（パッド割当を確定）。2026-09-11 全面改訂。** フレームを `OSS_FRAME`（ESD のみ）から
**`OSS_FRAME_GIO`（3 ステート双方向 IO 付き）** に変更したため。

## 1. フレームは `OSS_FRAME_GIO` を使う

`lef/TR-1um_frame_25x25.gds` の `OSS_FRAME_GIO` は 2,500 × 2,500 µm、
**`OSS_ESD_5V_DIO` × 14 + VDD パッド + VSS パッド**。

> **これで GIO の自作が不要になった。**
> 以前の版は「PDK には ESD セルしか無いので入力バッファ・出力ドライバは自作」
> と書いていたが、それは `OSS_FRAME`（`OSS_ESD_5V_ANA`）の話。
> `OSS_FRAME_GIO` の `OSS_ESD_5V_DIO` は**出力ドライバと 3 ステート制御を内蔵**している。
> 自作が要るのは（欲しければ）入力バッファだけ。

### パッド配置（`P8`=VSS / `P16`=VDD）

反時計回りに `P1` から。座標は GDS の原点（ダイの中心）から。

| 辺 | パッド（左→右 / 上→下） |
|---|---|
| 上 | `P2`(−584) `P1`(−216) **`VDD`**(+216) `P15`(+584) |
| 右 | `P14`(+584) `P13`(+216) `P12`(−216) `P11`(−584) |
| 下 | `P7`(−584) **`VSS`**(−216) `P9`(+216) `P10`(+584) |
| 左 | `P3`(+584) `P4`(+216) `P5`(−216) `P6`(−584) |

座標は LEF 実測（各辺 ±215.85 / ±584.15 µm）。

辺の中心線は ±1,040 µm、パッド開口は 80 × 80 µm。

## 2. `OSS_ESD_5V_DIO` の使い方

| ピン | 向き | 意味 |
|---|---|---|
| `OUT` | in（コア→パッド） | 出すデータ |
| `HIZ` | in（コア→パッド） | **1 でドライバを放す**。読むときは 1 |
| `PAD` | inout | ボンディングパッド。**上辺にコア側へのスタブも出ている** |

`HIZ=0` のとき **`PAD = OUT`（非反転）**。`HIZ=1` で高インピーダンス。
ngspice で確認済み（`claude/TR1um_pad_characterization.md`）。

| | |
|---|---|
| OUT→PAD 遅延 | **1 pF あたり約 0.17 ns**（CL=10 pF で 10.6 ns / 50 pF で 17.0 ns） |
| 3 ステート | enable 9.4 ns（CL=10 pF）/ disable 7.9 ns（負荷に依らない） |
| 入力容量 | `OUT` 36.2 fF / `HIZ` 86.8 fF |
| `PAD` の容量 | **4.8 pF**（パッド金属 + W=500 µm の ESD 素子） |
| 駆動能力 | VDD/2 で **PMOS +15.8 mA / NMOS −13.8 mA**。LED 直結も可 |

### 入力として使うとき

**入力バッファは入っていない。** `PAD` の上辺スタブをコアの標準セル入力に直結する。
振幅は 0〜5 V で同じ VDD なので論理的には問題ない。ただし 2 点注意:

- **`PAD` の容量 4.8 pF は外から見た負荷**。外部ドライバが弱いと立上りが鈍る。
  鈍った波形をそのままコアに配ると各段で貫通電流が増えるので、
  **パッドのすぐ内側に `BUF_X2` を 1 段置く**のが安全（`.lib` の `max_transition` は 16 ns）。
- **シュミット入力は無い。** `CLK` / `RSTN` にチャタリングやゆっくりした縁が来る
  可能性があるなら、外部で整形するか、シュミット（`IBUFS`）を自作する。
  TD4 を 10 MHz 以下で使うなら外部整形で足りる。

### 方向が固定のピンは `HIZ` を電源に固定する

出力専用なら `HIZ` を VSS に、入力専用なら VDD に落とす。
**`TIEHI`/`TIELO` は無い**ので、`HIZ` をレールに直結して配線する。
（ロジック側で `TIEHI`/`TIELO` が要らないことは合成で確認済み — 定数に繋がった
セル入力ピンは 4 つの top すべてで 0 個 → `claude/TD4_synthesis_mapping.md`）

## 3. 電源のつなぎ方

コア境界（内縁）に何が出ているかを抽出で確認した:

| | |
|---|---|
| **VSS** | **リング全周**に M1 と M2 の両方で出ている。どこからでも繋げる |
| **VDD** | **上辺の 1 箇所（x = 50〜350 µm）に M1 のタップが 1 本だけ** |

VDD の M2 リングはパッドの**外側**（±1,140 µm）を四辺とも回っていて、
コア側には出ていない。つまり **コアへの VDD はこの M1 タップから引き込むしかない**。

### 電流の経路は 2 つに分かれる

VDD ボンディングパッド（`P16`、上辺 x=+200）から先は**別々の枝**になる:

```
VDD パッド ─┬─ M2 外側リング（四辺）──→ 16 個のパッドセルの VDD
            │                              ← DIO の駆動電流 15.8 mA/本 はここ
            └─ M1 タップ（真下）──→ コア境界 ──→ コアの電源メッシュ
                                                ← コアの電流だけ
```

**DIO の駆動電流はコアの M1 タップを通らない。** M2 外側リングから直接供給される。
したがって M1 タップが運ぶのは**コアのロジック電流だけ**でよい。

### M1 タップの実寸

| 場所 | VDD/M1 の幅 |
|---|---|
| コア境界（y = 920〜933） | **300 µm**（x = 50〜350 の 1 本のバー） |
| その上（y = 934〜990） | **40 µm × 2 本 = 80 µm**（x = 150-190 と 210-250） |

くびれは **80 µm**。ここがコア電源の実効的な入口断面になる。
（TR-1um の PDK に電流密度／エレクトロマイグレーションの規定は無いので、
上限は各自の経験則で見ること。）

### したがってフロアプランは

1. コア境界の **300 µm の M1 バー**をバスバーの取り付け口にする
2. そこから M1 で幹線を引き下ろし、**M1/M2 の電源メッシュ**を組む
3. VSS はリング全周から取れるので、メッシュの VSS 側は四辺どこからでも繋げる

行の向きは、この「VDD が上辺 1 箇所から入る / VSS は全周」という非対称を
前提に決めること。

## 5. 案の見直し

### 案A — `td4_soc_arr`（書換可能プログラムメモリ内蔵）★採用

**パッド番号で直接割り当てる。**（`P8`=VSS / `P16`=VDD はフレーム固定）

| パッド | 信号 | 方向 | Load モード (EXEC=0) | Exec モード (EXEC=1) |
|---:|---|---|---|---|
| `P1` | `CLK` | in | 書込クロック | 命令実行クロック |
| `P2` | `WR` | in | 書込ストローブ | — |
| `P3` | `NIBSEL` | in | 0=下位 / 1=上位 ニブル | — |
| `P4`–`P7` | `D[3:0]` | in | 命令ニブル入力 | **IN ポート** |
| `P9` | `RSTN` | in | 非同期リセット | 同左 |
| `P10`–`P13` | `OUT[3:0]` | out | — | **OUT レジスタ（LED）** |
| `P14` | `EXEC` | in | 0 | 1 |
| `P15` | `CF` | out | — | キャリーフラグ観測 |

**14 信号でちょうど一杯。** 方向は固定なので `HIZ` はレール直結。

### 案B — `td4_soc_rom`（マスクROM内蔵）

14 信号（`CLK` `RSTN` `IN[3:0]` `OUT[3:0]` `PC[3:0]`）。
`PC[3:0]` を出さなければ 10 信号で済み、**4 本を TEG に回せる**。

### 案C — `td4_core`（命令メモリ外付け）— **非推奨ではなくなった**

以前は「双方向バス = GIO 自作が必要」なので非推奨としていたが、
**`OSS_ESD_5V_DIO` が 3 ステート双方向なので自作は不要**になった。

`CLK` `RSTN` `D[3:0]`（双方向）`IN[4]` `OUT[4]` `ALE` = **14** で収まる。
アドレス出力とデータ入力を `D[3:0]` で多重化し、`ALE` で区切る（CPI=2）。

ただし採らない理由は残る:

- **CPI=2 になる**（フェッチに 2 サイクル要る）。TD4 の CPI=1 という利点を失う
- 外付け ROM が要るので**チップ単体で動かない**
- バスの切替タイミング（`HIZ` の enable 7〜9 ns / disable 7.9 ns）を
  クロックに織り込む必要があり、検証項目が増える

**TEG として双方向バスを試すなら価値がある**が、本命は案A のままでよい。

## 6. 自作が必要な I/O セル — ほぼ不要になった

| セル | 用途 | 状況 |
|---|---|---|
| ~~`OBUF`~~ | 出力ドライバ | **不要**。`OSS_ESD_5V_DIO` が W=300/150 µm の駆動段を内蔵 |
| ~~`GIO`~~ | 3 ステート双方向 | **不要**。同上 |

## 7. パッド割当（確定）

パッド番号は**ダイの上辺左寄りから反時計回り**に振られている。各辺のパッドは
中心線から **±215.85 / ±584.15 µm**（LEF 実測。以前この文書が書いていた
±200/±600 は丸め値）。

| パッド | 辺 | 中心から | 信号 | 向き | `HIZ` |
|---|---|---:|---|---|---|
| `P2` | 上 | −584 | `WR` | in | VDD |
| `P1` | 上 | −216 | `CLK` | in | VDD |
| **`VDD`** (`P16`) | 上 | +216 | 電源 | — | — |
| `P15` | 上 | +584 | `CF` | **out** | VSS |
| `P14` | 右 | +584 | `EXEC` | in | VDD |
| `P13` | 右 | +216 | `OUT[3]` | **out** | VSS |
| `P12` | 右 | −216 | `OUT[2]` | **out** | VSS |
| `P11` | 右 | −584 | `OUT[1]` | **out** | VSS |
| `P10` | 下 | +584 | `OUT[0]` | **out** | VSS |
| `P9` | 下 | +216 | `RSTN` | in | VDD |
| **`VSS`** (`P8`) | 下 | −216 | 電源 | — | — |
| `P7` | 下 | −584 | `D[0]` | in | VDD |
| `P6` | 左 | −584 | `D[1]` | in | VDD |
| `P5` | 左 | −216 | `D[2]` | in | VDD |
| `P4` | 左 | +216 | `D[3]` | in | VDD |
| `P3` | 左 | +584 | `NIBSEL` | in | VDD |

### ビットの向き — **パッケージで上から下が MSB→LSB**

両バスとも、**ダイを立てて見たときに上にあるパッドほど上位ビット**になる。
バス番号とパッド番号の増減が逆になるのは辺の回り方が逆だからで、意図どおり。

```
   左辺 上→下          右辺 上→下
   P4 = D[3]           P13 = OUT[3]
   P5 = D[2]           P12 = OUT[2]
   P6 = D[1]           P11 = OUT[1]
   P7 = D[0]（下辺へ回り込む）  P10 = OUT[0]（下辺へ回り込む）
```

`D` は左辺 3 本 + 下辺 1 本、`OUT` は右辺 3 本 + 下辺 1 本に割れる。
**バスの端 1 本だけ辺が違う**ので、コア側の入力バッファ列／出力ドライバ列も
そこで折れる。フロアプランで `D[0]` と `OUT[0]` の取り回しを忘れないこと。

### `HIZ` と未使用 `OUT` の始末

- 入力専用パッド（9 本）は `HIZ` を **VDD** に直結してドライバを放す。
  このとき `OUT` はゲート入力なので**浮かせてはいけない**。**VSS** に落とす。
- 出力専用パッド（5 本）は `HIZ` を **VSS** に直結する。
- `TIEHI`/`TIELO` セルは無いので、いずれもレールへ直接配線する。

### 電源・タイミングから見た妥当性

- **`CLK` は上辺 (`P1`)**。VDD の M1 タップが上辺にあるので、クロックの
  入力バッファをタップ直下の低インピーダンス領域に置ける。ここは守れている。
- `RSTN` (`P9`, 下辺) と `EXEC` (`P14`, 右辺) は上辺から遠いが、
  `RSTN` は非同期・`EXEC` は動作中不変のモード信号なので**周期に効かない**。
- 出力 5 本のうち 4 本が右辺に寄るが、**DIO の駆動電流 (15.8 mA/本) は
  M2 外側リングから直接供給**され、コアの M1 タップを通らない（§3）。
  したがって出力を 1 辺に寄せてもコア電源には影響しない。
- `P15` (`CF`) が VDD パッドの隣に来る。出力の切替電流はリング側なので
  問題ないが、`CF` を高速に観測する用途では VDD リングのバウンスが
  乗りうることは頭に入れておく。

### コア側（RTL）の名前との対応

`hdl/rtl/td4_soc_arr.v` のポート名はパッド名と綴りが違う。P&R の I/O 結線で使う対応表:

| パッド名 | RTL ポート | 幅 |
|---|---|---|
| `CLK` | `clk` | 1 |
| `RSTN` | `rst_n` | 1 |
| `EXEC` | `exec` | 1 |
| `WR` | `wr` | 1 |
| `NIBSEL` | `nibsel` | 1 |
| `D[3:0]` | `d[3:0]` | 4 |
| `OUT[3:0]` | `out_port[3:0]` | 4 |
| `CF` | `cflag_o` | 1 |
